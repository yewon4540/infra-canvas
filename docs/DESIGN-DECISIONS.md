# Design Decisions

## 1. 설계 graph를 코드 생성의 입력으로 사용

리소스 다이어그램과 IaC를 각각 수정할 때 생기는 불일치를 줄이기 위해 Canvas graph에서 HCL을 생성합니다. 리소스 속성뿐 아니라 배치·연결 관계도 해석합니다.

대신 임의의 Terraform/OpenTofu 코드를 완전히 왕복 변환하는 편집기를 목표로 하지 않습니다. 지원하지 않는 리소스나 불명확한 관계는 명시적으로 드러내야 합니다. 현재 편집 graph는 설계 기준이고, AWS 실시간 상태의 완전한 복제본은 아닙니다.

## 2. 검토한 Plan을 실행의 기준으로 보존

사용자가 승인한 뒤 최신 설계로 다시 Plan을 만들면 승인 대상과 실행 대상이 달라질 수 있습니다. 이를 줄이기 위해 binary Plan artifact, checksum, backend metadata를 보존하고 해당 artifact를 실행합니다.

Plan은 single-use로 다룹니다. 실패 후 재시도에도 새 검토가 필요해 편의성은 줄지만, 부분 실행 이후의 상태를 새 Plan으로 확인할 수 있습니다. Checksum 검증은 파일 무결성 검사이며 artifact 저장소의 접근 통제를 대체하지 않습니다.

## 3. API 요청과 인프라 실행을 분리

OpenTofu 작업은 HTTP 요청보다 오래 걸릴 수 있습니다. Dramatiq worker에 실행을 맡기고 API는 작업 ID와 상태를 제공합니다. 진행 이벤트는 DB에 저장해 화면을 새로 열어도 추적할 수 있습니다.

이에 따라 queue·worker 운영 부담이 생깁니다. 현재는 polling 기반 단계 표시를 사용하고, 실시간 출력 스트리밍은 후속 범위로 둡니다.

## 4. Cross-account Role과 임시 자격증명 사용

대상 계정의 Role과 External ID를 검증하고 실행 시 AssumeRole합니다. 임시 자격증명은 DB에 저장하지 않고 subprocess 환경에 전달합니다. AWS write 권한은 onboarding template에서 명시적으로 활성화합니다.

Role 정책과 trust policy를 함께 설정해야 하므로 초기 연결 절차가 추가됩니다. UI의 승인과 AWS IAM의 허용 여부는 서로 다른 경계이며 둘 다 충족해야 실행할 수 있습니다.

## 5. AI 피드백과 필수 검증을 분리

설계 의도, 비용 성향, 예상 사용량에 따른 조언은 LLM이 설명하고, 일부 주요 구조적 오류는 코드로 검사합니다. 반복적으로 잡아야 하는 위험의 누락을 줄이면서 문맥에 따른 조언을 제공하려는 선택입니다.

Baseline은 포괄적인 보안 감사 도구가 아닙니다. 규칙 통과가 안전을 보장하지 않으며, LLM 응답도 사람이 검토해야 합니다. 런타임의 필수 규칙과 맥락 의존 조언의 범위를 구분합니다.

## 6. 발견과 관리 소유권을 구분

AWS/Kubernetes 운영 확장에서는 리소스 발견, 관계 해석, 화면 표시, IaC 관리 편입을 나눕니다. 조회한 리소스라고 해서 Eolgae가 변경할 수 있거나 관리 책임을 가진 것으로 취급하지 않습니다.

이는 후속 기능의 설계 방향입니다. 현재 live discovery/import는 구현돼 있지 않습니다. 먼저 읽기 전용 조회와 소유권 표시를 마련하고, 관리 편입은 기존 IaC와의 충돌 검토 및 승인 흐름을 별도로 설계할 계획입니다.
